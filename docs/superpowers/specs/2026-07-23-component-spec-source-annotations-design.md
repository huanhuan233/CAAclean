# ComponentSpec 数据来源标注设计

## 目标

在不修改原始 `component-spec-v1.2-template.yaml` 的前提下，生成一份逐字段标注版 YAML，说明每个字段值是否能从图纸、STEP、几何算法中获得，或必须由系统/人工定义。

## 分类口径

- `可以从图纸直接获得`：图纸文字、明细表或尺寸表明确给出，OCR/表格解析后可直接规范化。
- `可以从STEP直接获得`：STEP/B-Rep 中存在可确定查询的几何、拓扑或文件属性，只需常规几何测量。
- `可以获得但是需要推理和算法`：需要特征识别、圆周阵列检测、语义归类、标准库查询、坐标归一化或多源冲突解决。
- `无法获得`：属于系统 ID、库管理、发布策略、生成器实现、装配业务规则、审批信息或人工建模约定，不应从 STEP/图纸猜测。

`STEP可以直接获得` 指几何核可直接测量，不等于当前 mapper 已经接入。如果需要先判断“哪个圆柱面才是颈部”，则归入“需要推理和算法”。

## 输出规则

- 原始文件保持不变。
- 每个非空、非纯注释的 YAML 数据行追加 `@：分类；理由`。
- 原有行尾注释保留，`@` 标注继续位于 `#` 注释内，保证 YAML 仍可解析。
- 空行和纯说明注释不追加分类。
- 参数元数据如 `required`、`editable`、`status` 按“字段值的权威来源”分类，而不按参数本身是否可测量分类。

## 验收标准

- 输出文件数据行数与原文一致。
- 所有 YAML 数据行都包含且仅包含一个 `@：` 标注。
- 标注版可由 YAML 解析器正常加载，且去掉注释后的数据结构与原文一致。
- 另外给出自动检索、生成和装配所需的建议新增字段，同样使用 `@：` 格式。
