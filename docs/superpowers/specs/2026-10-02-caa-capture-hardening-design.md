# CAA 采集链路加固设计

日期：2026-10-02

范围：`caa_new` 原生采集、Worker 导入 PostgreSQL、Feature Center 数据呈现。按照架构分析报告的 1–8 项顺序交付，每项先有失败测试，再修复并验证。既有 `main` 工作目录及其中未提交文件不参与本次改动。

## 目标与不变量

- CATIA 采集仍是只读；不修改原始 CATPart/CATProduct。
- 原生程序可分别由 x86、x64 调用器运行；本机仅能实际编译并运行 x86，x64 以源码和目标契约检查，不能声称实编通过。
- 前端展示的数据必须经 Worker 完整导入 PostgreSQL；不从 JSONL 直接兜底展示。旧采集包仍可入库，新字段缺失时展示“未知/未采集”，不伪造成功。
- 不覆盖用户非采集目录，不删除未知暂存/备份目录；现有后端预创建的空输出目录仍允许使用。
- C++ 新增或修改的函数均配中文职责注释；纯计算与 Win32 边界优先放到可独立测试的深模块。

## 备选与选择

1. **增量深模块（采用）**：保持现有证据包和 JSONL 契约，逐项封装目录事务、文档生命周期、对象索引、状态汇总与重建判断，并补入库/前端测试。每项可独立回归，兼容已有模型和数据。
2. 原生采集全量重写：可统一接口，但风险大、难以复核旧 CATIA 模型兼容性，本轮不采用。
3. 仅在 Worker/前端补救：不能恢复丢失的原生特征和真实几何状态，本轮不采用。

## 顺序与模块边界

1. **输出事务安全**：`ArtifactRepository` 独占目录事务和所有权判断。解析器接收输出路径并规范化；拒绝卷根、重解析点以及无法证明可替换的非空目录。暂存/备份使用本次运行唯一名称与标记，不删除未知路径；失败时保留可恢复的旧输出。Worker 只负责申请输出目录、调用和记录日志，不管理原生程序的备份内部结构。
2. **关联 CATPart 类型化采集**：将“打开关联文档→枚举→属性/特征/工程语义/几何→关闭”封装为一个有生命周期的调用。原生绑定在文档关闭前消费，关联实例仍投影到现有装配树；不能拿关闭后的 CATIA 指针。旧对象/实例 ID 语义保持不变。
3. **大树索引**：在单个打开文档范围建立 `object_id → CATISpecObject` 索引，属性、特征、语义提取器共用。CATIA `IsEqual` 只作为引用匹配的受控退路，记录退路次数；关闭文档后索引失效，不进入序列化模型。
4. **几何状态**：拓扑提取完成后，以对象/实体关联为粒度写 `geometry_status`；明确“未采集”“无几何”“部分”“精确”“错误”。不得从全包 `geometry` 是否为空推断某个对象的状态。旧包缺字段时 Worker 按未知处理。
5. **采集策略与状态**：落实或移除未生效策略。`allow_partial_capture=false` 时任何必需阶段失败都不得提交；未知对象保留和旧投影由明确策略控制，默认兼容现有消费者。包状态由实际诊断、阶段和证据决定，不无条件标为 `partial`。

实现记录：`preserve_unknown_objects` 与 `enable_legacy_projection` 从未接入引擎，已移除这两个误导性开关；未知对象与旧投影继续始终保留，保障现有 PostgreSQL/前端消费者。若将来提供关闭旧投影的能力，必须先完成下游兼容与迁移，不能仅开一个布尔值。`allow_partial_capture` 现在通过包级结果模块生效。
6. **占位模块/诊断**：草图、身份、关联文档、几何、三角化模块的接口必须与真实产出一致。尚无采集能力的模块报告 `not_implemented`/`unavailable`，不能报告成功；有几何无三角形时不得声称网格可用。
7. **精确 B-Rep 路线**：按每个 ResultOUT body 的拓扑闭合性、引用完整性、每张必要面/边的精确参数判断。混合体降级为部分精确证据，不因其他实体有精确几何而宣称整体可精确重建。
8. **中文路径**：在 Win32/CAA 边界统一 UTF-8→UTF-16；存在性检查与 CATIA 文档打开使用同一宽字符路径。输出写入也处理中文路径，避免输入修好但写出失败。Worker 的 ASCII staging 继续兼容既有部署，但不是原生程序必需条件。

## 数据流与错误处理

`CadCapture.exe` 生成已核验的证据包 → Worker 读 manifest/JSONL 并在 PostgreSQL 事务中入库 → 后端节点、属性和处理状态 API 从库查询 → Feature Center 仅渲染 API 结果。原生新增状态沿现有 `property_facts`/manifest 契约传输；如需要新结构化字段，先做兼容迁移与入库测试，再接前端。任何采集或入库失败必须保留可诊断错误，不返回“解析完成”，不回退读取临时文件来填 UI。

## 验证

- 每项：失败测试→最小实现→相关测试通过→回归基线；记录已有失败并明确区分。
- C++：VS2008 纯核心测试、x86 CAA 构建；实件 CATPart/CATProduct、关联零件、中文路径与大型树抽样。当前机器不声称验证 x64 二进制。
- Python：Worker 产物检查、PostgreSQL 入库/查询、旧新 bundle 兼容及错误状态测试。
- 前端：类型检查和 Feature Center 属性/状态显示测试；验证只依赖数据库 API。
- 输出目录：空目录、合法旧采集目录、未知非空目录、卷根、预存同名暂存/备份、重解析点、提交失败恢复均需覆盖。
