# 干净的 YAML 上传编辑器设计

## 目标

ComponentSpec 编辑区不再以系统模板作为起点。新图元在没有保存过 YAML 时保持空白；用户上传 YAML 后，右侧显示该 YAML，左侧根据它的实际结构动态生成可编辑字段。

## 状态与界面

### 未保存、未上传

- 不创建 ComponentSpec 编辑文档。
- 左侧显示“上传 YAML 后生成字段”的空状态，不显示模板字段。
- 右侧显示醒目的“上传 YAML”按钮和 YAML 空状态。
- 不显示“系统生成”“当前编辑”“恢复系统生成”等模板相关入口。
- 保存与融合操作在没有工作文档时不可用。

### 已上传、尚未保存

- 浏览器解析上传的 `.yaml` 或 `.yml` 文件。
- 右侧立即显示上传内容和文件名。
- 左侧递归推断并显示该 YAML 的对象、对象数组、标量数组和标量字段。
- 左侧字段修改实时更新右侧 YAML。
- YAML 解析失败时保留原工作文档，并显示错误行列。

### 已保存

- 再次打开图元时，后端返回已保存的 YAML、数据和源文件名。
- 前端直接恢复 YAML 工作文档和动态字段。
- 保存继续持久化完整的 `data`、`yaml` 和 `source_filename`。

## 数据判定

- `saved: false` 表示没有持久化工作文档；即使兼容接口返回了模板数据，前端也不得据此创建编辑器。
- `saved: true` 且 YAML 有效时，创建动态编辑器。
- 本地离线草稿只有在确实存在用户上传或编辑的 YAML 时才可恢复。

## 删除的模板行为

- 移除 YAML 编辑区的系统模板基线。
- 移除“系统生成”页签与“恢复系统生成”操作。
- 移除首次打开时通过 `component-spec-v1.2.json` 构造编辑文档的前端兜底。
- 后端模板能力可保留给其他调用方，但不得自动进入该上传编辑流程。

## 验证

- 新图元打开时编辑状态为空，左右两侧不出现模板字段或模板 YAML。
- 上传 YAML 后同时得到动态字段与 YAML 预览。
- 字段编辑后 YAML 同步且保存载荷完整。
- 已保存 YAML 重新打开后正确恢复。
- 非法 YAML 不替换现有文档。
- 前端测试、类型检查和生产构建通过。
