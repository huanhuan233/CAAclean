# 图元草稿与抽屉编辑设计

## 目标

- 新建图元时 STEP 与二维图纸均为可选，允许先保存空草稿。
- 已有图元使用同一个右侧抽屉编辑分类、名称、标准号和版本。
- 编辑时未重新选择的来源文件保持不变；选择新文件才替换对应来源并重新解析。
- 允许先上传二维图纸。没有 STEP revision 时暂存图纸，补传 STEP 后自动创建图纸解析任务。

## 接口

- `POST /api/component-builds`：元数据必填，两个文件均可选；无来源时返回 `draft`。
- `PATCH /api/component-builds/{build_id}`：更新元数据并可携带任意来源文件。
- 图纸先于 STEP 到达时，保存到按 build ID 隔离的待处理目录，并以 `waiting_for_step` 投影到文件树。

## 状态与错误

- 无文件：`draft`。
- 只有 STEP：STEP 正常解析，图纸显示待上传。
- 只有图纸：图纸显示等待 STEP，不把它标记为失败。
- 补齐或替换来源后：仅重新处理被替换以及受 revision 变更影响的来源。
- 文件扩展名仍按各自类型校验；编辑失败保留图元记录及未替换来源。

## 界面

- 上传区域移除必填星号，并提示“可稍后补充；未选择则保留现有文件”。
- 版本详情提供“编辑图元”，打开同一个抽屉并回填元数据。
- 抽屉标题和提交按钮区分“新建”与“保存修改”。
- 文件树持续展示两种来源节点，使缺失、等待和解析状态可见。
- STEP 几何解析与二维图纸抽取两行各提供独立的“开始解析”按钮。
- 只有已关联对应来源且当前未在解析时按钮可用，点击后重新启动该来源的真实解析任务。

## 验证

- 后端覆盖空草稿、单文件、图纸先传、后续补 STEP、纯元数据编辑和来源保留。
- 前端执行类型检查与测试构建。
- 页面核对新建空草稿、打开编辑抽屉、保存修改以及文件状态展示。
