# CAA ZIP ASCII 工作路径修复设计

## 背景与根因

CATIA R21 CAA_NEW 通过 `char**` 接收命令行参数，再以窄字符串构造 CATIA 文档路径。上传的 ZIP 包含中文共同顶层目录时，传入 `CATDocumentServices::OpenDocument` 的路径发生编码损坏，导致 `CATIA document open failed`，进程以退出码 2 结束。

现场证据：同一个根装配 `500.000 A.CATProduct` 在中文路径下稳定快速失败；复制到纯 ASCII 路径后可越过文档打开阶段并持续执行解析。Worker 当前选中的入口已是编号最小的 `500.000 A.CATProduct`，入口选择不是故障原因。

## 修复范围

仅调整 CATIA Worker 对 ZIP 源文件的解包布局：

- ZIP 中所有文件若共享同一个顶层目录，解包时剥离该共同顶层目录。
- 文件在该目录内部的相对层级和文件名保持不变，避免破坏 CATProduct 对依赖文件的相对引用。
- 根 CATProduct 继续使用现有选择规则；本数据集应选择编号最小的 `500.000 A.CATProduct`。
- 路径越界检查必须基于剥离后的目标路径继续生效。
- 不修改上传的原始 ZIP，不修改 CATIA 文件内容，不改动 CAA 二进制。

若 ZIP 没有唯一共同顶层目录，则维持当前解包布局。若剥离后路径本身仍含非 ASCII 文件名或更深层非 ASCII 目录，本次修复不重命名它们，避免破坏装配引用；这种情况继续返回明确的 CAA 打开失败，留给后续原生 Unicode 入口改造处理。

## 数据流

1. Worker 将上传内容保存为 `source.zip`。
2. 读取 ZIP 中全部非目录条目，并计算是否存在唯一共同顶层目录。
3. 对存在共同顶层目录的条目去掉第一段路径，再执行越界校验并解包到 `source-bundle`。
4. 从解包结果中寻找 CATProduct，沿用现有根装配选择逻辑。
5. 将选中的 ASCII 工作路径交给 CAA_NEW。

## 错误处理

- 去掉共同前缀后若条目路径为空，忽略该目录占位条目。
- 任何绝对路径、父目录穿越或越出 `source-bundle` 的条目仍返回 `catia_source_bundle_invalid`。
- 不吞掉 CAA_NEW 的真实退出码和日志。

## 测试

新增回归测试，构造包含中文共同顶层目录的 ZIP，并断言：

- 解包后的入口路径不再包含该中文顶层目录；
- 入口文件为编号最小的 `500.000 A.CATProduct`；
- 同目录的子 CATProduct/CATPart 依赖均被保留；
- `../` 越界条目仍被拒绝。

测试先在现有实现上失败，再实施最小生产代码修改并验证相关 Worker 测试集。
