# Live YAML 驱动 ComponentSpec 编辑器设计

## 目标

将“上传 YAML”从旁路预览改为 ComponentSpec 的主编辑流程：

1. 用户上传任意合法 YAML。
2. 系统解析 YAML 并在左侧自动生成可编辑字段。
3. 用户修改字段时，右侧 YAML 预览实时更新。
4. 保存后再次打开仍能恢复结构化字段、未知字段、字段顺序和 YAML 注释。

本功能必须兼容已有固定 v1.2 ComponentSpec，也必须支持 v1.3 或其他版本以及模板中没有的字段。

## 单一工作文档

弹窗内只维护一份“当前工作文档”，不再把“本地上传 YAML”和“ComponentSpec 字段”作为两套互不相干的数据。

工作文档包含：

- YAML AST：用于保留注释、字段顺序、标量样式和引号。
- 结构化数据：用于字段编辑、数据融合和后端检索。
- 动态字段定义：用于生成左侧表单。
- 来源信息：`system`、`upload`、`manual` 或 `fusion`。
- 文件名、是否已修改、是否已保存及解析错误。

“系统生成”和“当前编辑”是同一文档的两个可切换版本：

- 系统生成：后端模板或数据融合生成的基线。
- 当前编辑：上传后或人工修改中的实时版本。

恢复系统生成会明确替换当前编辑版本；不得静默覆盖用户修改。

## YAML 解析与动态字段

前端将 `yaml@2.8.3` 声明为直接依赖，并使用 `parseDocument` 解析上传内容。

上传要求：

- 文件扩展名为 `.yaml` 或 `.yml`。
- YAML 无解析错误。
- 根节点必须是 mapping/object。
- 解析失败时显示行列和错误原因，保留当前工作文档。

字段生成规则：

- mapping 生成对象分组。
- sequence of mappings 生成可增删的对象数组。
- sequence of scalars 生成标量数组编辑器。
- string、number、boolean、null 生成对应输入控件。
- 混合数组或 YAML 特殊节点提供通用 YAML/JSON 文本编辑控件，不能丢弃。

已知字段按当前模板中相同 path 合并中文标签、说明、必填、只读、来源和类型信息。未知字段使用 YAML key/path 作为标签，并根据实际值推断编辑器类型。任何未知字段都必须保留。

## 实时更新

`ComponentSpecFieldEditor` 除了更新值，还向上冒泡精确字段 path。

字段变化时：

1. 使用 path 更新 YAML AST 对应节点。
2. 从 AST 重新得到结构化数据。
3. 立即刷新右侧“当前编辑”预览。
4. 标记文档为未保存。

对象和数组增删按其节点 path 更新。替换数组节点时允许重排该数组内部格式，但必须保留数组外部及未修改节点的注释和顺序。

预览无需每次请求后端。前端 AST 负责即时预览；后端仅在保存时再次解析和校验，保证持久化内容有效。

## 后端持久化

不新增数据库列。`component_spec_drafts.data` 使用向后兼容的文档封装：

```json
{
  "__format__": "component_spec_document_v1",
  "data": {},
  "yaml": "",
  "source_filename": null
}
```

兼容规则：

- 旧记录若没有 `__format__`，整体视为原有 `data`，YAML 用模板渲染生成。
- 新记录保存完整结构化数据和 YAML 文本。
- API 返回时解包为 `data`、`yaml` 和动态 schema 所需的模板元数据。
- 数据融合读取解包后的 `data`；融合保存后生成新的系统 YAML。

保存接口接收：

```json
{
  "data": {},
  "yaml": "",
  "source_filename": null
}
```

后端使用 `ruamel.yaml` 再次解析 `yaml`，要求根节点为 mapping，并校验解析结果与 `data` 等价。校验失败返回 422，不写入数据库。

当前 `3dcad` Conda 环境已经安装：

- `ruamel.yaml 0.19.1`
- `PyYAML 6.0.3`

`backend/requirements.txt` 已声明 `ruamel.yaml`，因此不重复安装。前端 `yaml@2.8.3` 必须通过 `pnpm` 添加为直接依赖；Conda 包不能供 Vite 浏览器代码使用。

## API 与界面流程

打开弹窗：

1. 获取保存的 ComponentSpec 文档。
2. 若有持久化 YAML，解析为工作文档。
3. 若是旧记录，使用结构化数据生成基线 YAML。
4. 左侧显示动态字段，右侧显示当前 YAML。

上传 YAML：

1. 读取并解析。
2. 生成动态字段。
3. 自动切换为“当前编辑”。
4. 左右两侧同时更新。

保存：

1. 前端提交当前 `data + yaml + filename`。
2. 后端校验并原样持久化 YAML 文本。
3. 返回保存后的文档，清除未保存状态。

数据融合：

1. 对当前结构化数据执行融合。
2. 保留未知字段。
3. 生成新的系统基线和当前编辑 YAML。

## 错误处理

- YAML 语法错误：显示行列，不替换当前文档。
- 根节点非对象：拒绝上传。
- 数据与 YAML 不一致：保存返回 422。
- 后端不可用：允许继续本地编辑，并把完整 YAML 工作文档暂存到浏览器。
- 切换图元或关闭存在未保存修改的弹窗：弹出确认，不静默丢失。

## 测试

前端测试覆盖：

- 解析带注释、未知字段和不同 schema version 的 YAML。
- 动态生成对象、数组和标量字段。
- 按 path 修改后 YAML 实时变化，未修改注释仍存在。
- YAML 错误不会替换当前文档。
- 上传、编辑、预览、保存和恢复系统版本的状态流。

后端测试覆盖：

- 新旧存储格式兼容。
- 保存并恢复任意未知字段与 YAML 注释。
- YAML 与 data 不一致时返回 422。
- 数据融合读取封装后的 data 并保留未知字段。

验收使用真实 `flange-001` 和一份 v1.3 YAML：

- 上传后左侧立即生成可编辑字段。
- 修改 `identity.name` 后右侧预览即时更新。
- 保存并重新打开后字段值、未知字段和注释仍存在。
