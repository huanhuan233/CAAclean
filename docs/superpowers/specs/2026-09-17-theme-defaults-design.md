# 前端主题默认配置固化设计

## 目标

将用户当前确认的主题与页面配置固化为应用默认值。开发环境、首次访问的生产环境、生产环境升级后的已有浏览器，以及“重置配置”操作，都应采用同一套默认配置；主题抽屉仍然保留，用户可以在默认值基础上临时调整。

## 固化配置

- 主题模式：亮色
- 推荐配色算法：关闭
- 主色：`#0632F6`
- 信息色：跟随主色
- 成功色：`#52C41A`
- 警告色：`#FAAD14`
- 错误色：`#F5222D`
- 布局模式：垂直布局
- 滚动模式：主体滚动
- 页面切换动画：开启
- 页面切换动画类型：滑动（`fade-slide`）
- 顶栏高度：45px
- 面包屑：显示
- 面包屑图标：显示
- 标签栏：显示
- 标签栏信息缓存：开启
- 标签栏高度：44px
- 标签栏风格：谷歌风格（`chrome`）

未在用户截图中变更的配置保持现状，不扩大本次修改范围。

## 实现设计

在 `frontend/src/theme/settings.ts` 中修改 `themeSettings`，使开发环境和“重置配置”直接使用上述值。

同时在同一文件的 `overrideThemeSettings` 中声明本次变更的最小覆盖字段。生产环境初始化时，现有的 `initThemeSettings` 会按构建标识执行一次覆盖，从而迁移浏览器里已有的旧主题缓存；覆盖完成后仍沿用现有持久化机制，允许用户继续调整。

不新增状态、不修改主题抽屉交互，也不删除浏览器现有缓存。

## 数据流

1. 应用启动时调用 `initThemeSettings()`。
2. 开发环境直接读取新的 `themeSettings`。
3. 生产环境把新的 `overrideThemeSettings` 一次性合并到旧缓存。
4. Pinia 主题 Store 继续生成 CSS 变量，并保存后续用户修改。
5. “重置配置”继续读取 `themeSettings`，因此回到本设计中的固定默认值。

## 异常与兼容性

- 仅覆盖已确认字段，旧缓存中的其他配置继续保留。
- 使用现有类型约束，错误字段名会在 TypeScript 检查中暴露。
- 不改变本地存储结构，不需要清理缓存或编写数据迁移脚本。

## 验证

- 添加或更新主题配置单元测试，断言上述默认值与覆盖值一致。
- 运行前端类型检查。
- 运行相关主题测试。
- 在开发页面刷新后检查主色、顶栏高度、滚动模式、面包屑和标签栏配置。
